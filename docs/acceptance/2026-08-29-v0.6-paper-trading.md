## Scenario covered

The reproduction runs 22 weekday sessions from 2025-01-02 through 2025-01-31 with
the same hash-pinned input family for all accounts:

| Account/sleeve | Policy | Sessions | Rebalances | No-op sessions | Fills | Ledger events |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `40000000-...0101` | manual `equal_weight` | 22 | 5 | 17 | 8 | 112 |
| `40000000-...0102` | auto `momentum_12_1` | 22 | 3 | 19 | 3 | 92 |
| `40000000-...0103` | stale-data probe | 1 | 0 | 0 | 0 | halted |
| `40000000-...0104` | `max_position_weight=0.4` probe | 1 | 0 | 0 | 0 | rejected |

The main sleeves prove separate account identities, deterministic target construction,
manual and recorded auto approval, close-to-next-open simulated fills, no-op days,
and the split, cash-dividend, and delisting action events. The stale probe halts on
missing first-session prices. The risk probe rejects the proposed target with the
`max_position_weight` code and emits no order.

The harness invokes each CLI operation in a separate Python process. Repeating the
first proposal and manual approval returns the identical result, while the auto sleeve
proves duplicate-cycle idempotency. The retained checks also cover ledger rebuild,
byte-identical backup copy/restore, and reconciliation of every valuation.

- appending its initial cash event is idempotent;

## Reproduction commands

```sh

```

Run only the process-boundary reproduction:


`report`, `rebuild`, and `reconcile` commands are documented in
[`docs/how-to-use.md`](../how-to-use.md). `current_research_only` inputs are allowed
for explicitly recorded forward or installation-replay paper runs; v0.5 historical
backtests continue to require `backtest_safe` inputs.

## Accepted boundary and non-goals

The local append-only paper ledger is the source of truth. PostgreSQL stores an
immutable account/event envelope for operator reporting, and Grafana's
`paper-portfolio` dashboard reads that projection. Derived positions, cash, and NAV
are rebuildable from the event history.

The accepted v0.6 boundary does not include real-money order submission, broker
connectivity, leverage, margin, options, futures, shorting, intraday execution, or a
claim of live performance. The optional broker sandbox was deliberately not used.
Accumulating a genuine wall-clock forward record and integrating the accepted pieces
into the full collect-to-paper product remain v1.0 work.
