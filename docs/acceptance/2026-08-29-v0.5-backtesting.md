## Determinism, recovery, and lineage

The acceptance proves that:

- a clean replay produces the same experiment and result identity;
- the result manifest and every published artifact file are byte-identical on replay;
- changing one input manifest requires a new experiment identity;
- an interrupted run resumes from an authenticated immutable checkpoint and matches
  the uninterrupted result;
- result manifests validate their experiment, input, row, and artifact hashes;
- the PostgreSQL experiment/run catalog is idempotent for registration, start, and
  terminal events; and
- retrying a failed run creates a separate operational run while preserving the
  completed run and append-only event history.

The retained bias artifact is
`a58f5050-036e-59f3-afab-a800212a57f2`, with 13 probes and status `passed`:

- same-session execution when next-session execution is required;

## Reproduction commands

Run the local artifact and bias acceptance:

```sh
make backtest-reproduction
```

Run the isolated PostgreSQL metadata recovery acceptance:

```sh
make backtest-acceptance
```

For an operator-run experiment, use `invs-backtest` with a complete experiment
specification and its local artifact root:

```sh
docker compose run --rm --no-deps jupyter invs-backtest run \
  --spec /data/research/spec.json \
  --data-root /data/research/inputs \
  --results-root /data/research/results
```

The `validate` command checks a published manifest without mutation, and `compare`
compares immutable result manifests. Checkpoints can be enabled with
`--checkpoint-root`; `--stop-after-session N` deliberately interrupts a run and
`--resume` continues from the authenticated checkpoint.

## Accepted boundary

v0.5 provides a transparent, daily, long-only simulator with explicit decision and
execution clocks, conservative actions/costs/FX, baseline strategies, versioned
metrics and risk-free policy, immutable result artifacts, PostgreSQL run lineage,
and fail-closed historical bias checks.

The internal Python simulator is canonical. LEAN is not a v0.5 runtime dependency
and no semantic-equivalence claim has been made. Rolling calibration execution,
portfolio construction, paper trading, broker submission, intraday simulation,
shorting, and margin remain later roadmap boundaries.
