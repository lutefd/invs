# v0.3 feature-platform acceptance — 2026-08-29

## Result

The v0.3 exit gate passed on the repository `main` branch. The reproducible
acceptance is implemented in
[`python/tests/test_v03_feature_acceptance.py`](../../python/tests/test_v03_feature_acceptance.py)
and uses only temporary test roots; no provider credential or external evidence
archive is required.

## Scenario covered

The fixture creates 20 deterministic security IDs and 20 explicit security-to-issuer
mappings, three manifest-backed canonical datasets, and two monthly decision times:

- `market-basic` consumes three daily price rows per security;
- `fundamental-growth` consumes reviewed SEC `Revenue` and
  `OperatingIncomeLoss` facts for 2023 and 2024; and
- `macro-state` consumes CPIAUCSL rows for 2023 and 2024, including a 2024 revision
  available on 2025-01-15.

Each family is first given one prepublished child artifact, then the batch runner is
called for the full 20-security × 2-date matrix. The existing child is reused without
changing its bytes or modification time. The resulting 40 accepted partitions per
family are compared with a fresh publication from an independently copied clean data
root; the complete feature trees match byte-for-byte.

The decision boundary is visible in the published rows: the first fundamental
decision has no prior-year revenue growth, while the second has `0.2`; macro
year-over-year change is `0.1` before the revision and `0.15` after it. The quality
report filters physical input parts by `available_at`, `observed_at`, period end, and
macro vintage before reporting typed nulls and raw locators.

## Fail-closed probes

The same acceptance test verifies that each of these mutations is rejected:

1. a selected canonical input part with changed bytes;
2. a selected child feature output part with changed bytes;
3. a changed feature registry document supplied to the batch reader;
4. a changed taxonomy mapping registry reused against an existing fundamental batch;
5. a changed universe member list with the original universe fingerprint.

The feature-quality suite additionally verifies explicit rejected partitions, the
`insufficient_history` null vocabulary, stale-input age, source contribution, and
raw locators. Its report is defined by
[`feature-quality-report.schema.json`](../../schemas/feature-quality-report.schema.json).

## Reproduction commands

The runtime uses the repository's Jupyter image because the host shell does not carry
the Python research dependencies:

```sh
docker compose run --rm --no-deps \
  -v "$(pwd)/schemas:/repo/schemas:ro" \
  -e INVS_SCHEMA_ROOT=/repo/schemas \
  jupyter sh -c "pip install -q -e '.[dev]' && \
    python -m pytest tests/test_feature_quality.py tests/test_v03_feature_acceptance.py && \
    python -m ruff check research/feature_quality.py tests/test_v03_feature_acceptance.py"
```

Observed result: `5 passed`; Ruff reported `All checks passed!`.

The dependency-free schema catalog check also passed:
